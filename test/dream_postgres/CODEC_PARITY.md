# Codec parity with the pgo fork

`test/driver/PARITY.md` (on the driver branch) lists the 278 test cases of the pgo fork. It sends 157 value cases to the client codecs. This file maps each of these 157 cases to the codec test that holds the same value and direction, or the same edge.

Counts: 84 covered by tests that were there before, 36 covered by new tests, 37 different by design. No case shows a codec bug.

## How to read a row

- A `codec_probe_test.gleam` label runs on each server, PostgreSQL 16 to 19. A `writes` probe sends the value as `$1` and compares the server's text. A `reads` probe reads the server's value of a text and compares the Gleam value.
- Each other label is a unit test against the exact bytes. The text before `›` is the group of the test in its file.
- The new tests are in `codec_parity_test.gleam` and in the parity probes of `codec_probe_test.gleam` (after the comment "The value cases of the pgo fork that the probes above do not hold").
- "Different by design" gives the reason, then the test that shows what the codec does in its place.

## Types with no built-in codec

For a type with no built-in codec, `codec.custom` reads and writes the text form of the type:

```gleam
codec.custom(
  type_name: "pg_lsn",
  to_text: fn(text) different by design: the server never gives a parameter the type anyarray; codec.array writes to the concrete array type of the parameter. Test: codec_parity_test.gleam: `types with no built-in codec › an array does not take anyarray` / codec_probe_test.gleam (each of PostgreSQL 16 to 19): `writes int4[] {1,NULL,3}`,
  from_text: Ok,
  placeholder: "",
)
```
